# Token ideas (not built)

**There is no token code in this repository, and none should be written without legal review first.** Anything below would likely be a financial product in many jurisdictions (securities, gambling and money-transmission rules among them). This file is a list of ideas so they are not lost; it is not a plan.

v1 has no wallets, prices, tokens or crypto UI (DESIGN.md don'ts).

## Ideas

- **A single faith token.** One token for the whole game, not one per faith. It could, for example, be earned for conversions, schisms that hold, and boss breaks, and spent on cosmetic things like glass styles or card frames. No game-rule effect: the rules engine never reads a balance.
- **Staking pools per faith.** Holders could back a faith for a season, with a share of a season-end pool going to backers of the top faiths. This is the part most likely to be regulated as wagering; it would need the strictest review.
- **A bonding-curve launch.** Price set by a bonding curve rather than a sale, so there is no fixed raise. It still needs a securities analysis, disclosures, and a decision about who can buy (geofencing, KYC).
- **Airdrops to participants.** Retroactive drops to prophets, followers and reporters by real participation (conversions, forks published, reports that were upheld), with anti-sybil rules. Simple, but it still needs a tax and securities review.

## Constraints any version must respect

- The rules engine decides outcomes. No token, stake or balance may change conviction, leanings, conversions, schisms or strikes (GAME.md principle 1).
- Invented faiths only. Nothing financial may attach to real religions or real people.
- Off by default and separable: the game must be fully playable with no token at all.
- Legal review before any code: securities, gambling, consumer protection, tax, sanctions and age restrictions, per jurisdiction.
