# DECISIONS

One line each: decision, why, alternative rejected.

- Next.js 16 (latest stable) with the App Router; why: current major, Auth.js v5 beta supports it; rejected Next 15 (older, no benefit).
- Prisma 7 with driver adapters for both databases; why: Rust-free client, one adapter seam for Postgres and PGlite; rejected Prisma 6 (engine binaries, older adapter API).
- PGlite fallback via `pglite-prisma-adapter` in-process, data in `.pglite/`; why: zero external services and no extra server process; rejected a PGlite socket server (one session shared by all connections makes interleaved transactions unsafe).
- A lockfile guards `.pglite/` so a second process fails fast with a clear message; why: PGlite is single-process and would corrupt on concurrent open; rejected silent sharing.
- Migrations are SQL generated by `prisma migrate diff`; `pnpm db:migrate` runs `prisma migrate deploy` on Postgres and a small runner on PGlite that applies the same files and records them in `_prisma_migrations`; why: Prisma's CLI cannot open in-process PGlite; rejected separate schemas per database.
- Playwright pinned to 1.63.0; why: matches the browser build pre-installed in this environment; rejected `playwright install` (network download).
- Tailwind 4 with the token mapping in `tailwind.config.ts` loaded through `@config`; why: DESIGN.md asks for the config mapping, v4 is current; rejected Tailwind 3.
- Ticks are global and monotonically increasing per world; seasons store `startTick`, and the header shows the season-relative tick ("Tick 142 of 168"); why: seeds stay unique across seasons; rejected resetting tick numbers each season.
- `/e/[id]` serves both encounters and card share pages: it resolves an Encounter id first, then a ChronicleEvent id (schism cards have no encounter); why: GAME.md and the build prompt both claim `/e/`; rejected a second `/c/` route.
- Engine-created rows use deterministic ids hashed from `(worldSeed, tick, purpose, index)`; why: the seed is reproducible end to end and replay tests can address rows; rejected random cuids for engine rows (user-created rows still use cuid).
- `resolveEncounter` takes the sampled noise and backlash roll as inputs, and `encounterNoise()` derives them from the seed; why: the roll stays a pure function of stored inputs, so replay and the GAME.md §6 worked example are exact; rejected deriving noise inside the roll (the worked example's +0.030 is not reachable from a real seed).
- Troll backlash applies only when the target did not convert; why: lowering the leaning to a faith the agent just joined is meaningless; rejected applying it unconditionally.
- Integration tests use a fresh in-memory PGlite per test file with the real migration SQL applied; why: isolated, fast, zero services, and they exercise the same migrations as production; rejected a shared on-disk test database.
- A unit test parses the migration SQL and fails if any foreign key is not the leading column of an index, primary key or unique constraint; why: "indexes on every foreign key" is enforced, not hoped for; rejected manual review.
- `GospelDraft.faithKey` is an empty string for new gospels instead of NULL; why: Postgres treats NULLs as distinct, which would break the one-draft-per-user unique key; rejected a partial unique index (not expressible in Prisma).
- S, R, noise, social, style modifier and pull are rounded to 9 decimals inside the roll; why: 0.25+0.2+0.25+0.075+0.075 evaluates to 0.8499999…, which would make a 0.85 sermon fail `bossMinScore`; rejected epsilon comparisons scattered through the rules.
- Fork change ratio is max(added, removed) over the larger count of non-blank lines; why: blank-line padding cannot fake a schism; rejected counting raw lines.
- At most one agent schism triggers per tick (candidates roll in id order); why: keeps the chronicle legible and the season cap simple; rejected multiple same-tick schisms.
- A silenced apostle still consumes its schedule draws; why: silencing one faith must not reshuffle every other faith's targets for the same seed; rejected skipping its draws.
- The old faith's leaning on conversion is the post-roll conviction (25 in the §6 example), not the pre-roll one; why: that is the conviction the agent held at the moment it left; rejected the pre-roll value.
- The linter matches per line on NFKC-normalized text with zero-width and bidi characters removed, and flags hidden characters on the raw line; why: "ig​nore your" is caught both as hidden text and as an agent instruction; rejected matching only the raw text.
- Real-faith and public-figure terms use letter-boundary regexes (not `\b`) so "Popes" or "imamate" do not trip "pope"/"imam" while "Vatican." does; why: fewer false positives on invented words; rejected substring matching.
- Denylist hits are content problems, not heresy: they block publish but never add a strike; why: heresy is the injection mechanic, while real-faith references are a content rule (GAME.md §13); rejected treating them as heresy.
- Prompt modules interpolate only `fenceUntrusted`, `fenceList`, `fenceExchange` or `trusted(number | boolean | enumValue(...))`; a test greps `lib/llm/prompts/` for any other `${…}`, string `+` or `.concat`, and a second test feeds a sentinel through every input field and asserts it never appears outside a fenced block; why: both static and behavioral proof of §12.1; rejected a lint rule alone.
- Faith, apostle and agent names are fenced like gospel text; why: prophets write faith and apostle names, so they are untrusted; rejected treating names as trusted.
- The Anthropic provider sends loose "wire" schemas through structured outputs and validates with the strict zod schema afterwards (bounds, enums, lengths); why: JSON-schema strict mode does not enforce numeric ranges; rejected relying on the API to bound scores.
- No server-side refusal fallback parameter; a refusal, cut-off or invalid output is retried once and then replaced by the MockProvider with `fallback = true`; why: the game must never stall on a model decision, and Mock keeps it deterministic; rejected the beta `fallbacks` parameter (adds a second model path to audit).
- Per-role model, output budget and effort live in GameConfig (`llmModels`, `llmMaxTokens`, `llmEffort`): Sonnet 5.5 for sermon, judge and amendment, Haiku 5.5 for reply, memory, post and moderation; why: GAME.md §16 asks for a cheaper model for reply and memory; rejected one model for every role.
- The mock apostle occasionally goes off-script (Troll about 1.2%, Zealot 0.3% of encounters), half with linter-visible lines and half with paraphrases only the judge catches; why: heresy must happen in a keyless world for the mechanic to be visible; rejected seeding heresy events by hand.
- A tick is claimed by inserting `TickRun(worldId, tick)` (unique), computed in memory (rules plus LLM calls), and committed in one transaction whose first statement is `UPDATE World … WHERE currentTick = tick − 1 AND stateVersion = v`; a stale or failed run can be taken over; a conflict retries the whole tick once; why: idempotent under the cron, the CLI and the admin button at once, without holding a transaction open across LLM calls; rejected a long transaction around the LLM calls.
- Encounters run in parallel (pool of 4) from start-of-tick state, and rolls apply in schedule order against the running state; why: matches GAME.md §5.3–4 and keeps replay exact; rejected sequential LLM calls.
- The World starts season 1 with founding flocks (`initialConviction` 20–90) and the rest Unaligned; why: gives "change this season" a meaning and uses the `initialConviction` rule; rejected an all-Unaligned start.
- Agent-schism founders keep `faithId` set to their new faith, with `isFounder = true`, and every share count excludes founders; why: profiles can say "founder of X" while share ignores apostles (GAME.md §10.3); rejected nulling the founder's faith.
- Agent-schism followers and human-fork movers both get `forkMoverConviction` (40) in the new faith; why: GAME.md only fixes it for forks, and one rule for both kinds of schism is simpler; rejected keeping their old conviction.
- The memory summary folds in the entries that drop out of the visible window every `memorySummarizeEvery` new entries, from the season start; why: the window and the summary never overlap; rejected re-summarizing the whole history.
- Mock-judge calibration (mock behavior only) aims for S ≈ 0.5 against R ≈ 0.45: about 80 conversions in 140 ticks and a few agents left Unaligned; why: a world that moves but does not churn; rejected a harsher judge (nobody moves) or a kinder one (everyone moves every tick).
- The seed builds the world through the same services users hit (`publishFork`, `editGospel`, `runTick`); seed-only nudges are a raised `agentSchismChance` passed as a per-tick `configOverride` in the second half (never stored on the world), and the fork happens at the first tick from 126 where the seeded schism pull would move at least 2 agents; why: the brief allows picking seeds or nudging config in the seed only; rejected special-casing the engine.
- The Reformed Kettle forks at tick 126–136 instead of the mockup's 138, and takes the first free glass if Ruby is gone; why: the world ends at tick 140 and agent schisms may claim Ruby first; rejected hard-reserving a palette color.
- Mock warmth bases are evened out (Gentle 2.4, Scholar 2.3, Mystic 2.2, Zealot 1.9, Troll 1.7), and founding flocks are 9/8/7/5/7 with 9 unaligned; why: the seeded share distribution should resemble the Nave mockup (no single runaway faith); rejected per-faith judge bias.
- `pnpm db:seed` truncates every app table first and is deterministic: two runs give the same digest (`pnpm tsx scripts/dump.ts`); why: a reseed must be safe and reproducible; rejected incremental seeding.
- Auth.js v5 uses JWT sessions with the Prisma adapter (users, accounts, verification tokens); why: the dev credentials provider requires JWT, and one strategy for both providers is simpler; rejected database sessions.
- The Prisma adapter is built inside Auth.js's async lazy config (the PGlite client opens lazily), with `createUser` overridden to assign a unique public handle from the email; why: our User has a required `handle`; rejected a separate handle onboarding step.
- `requireUser()` reloads the user from the database on every call (cached per request), so bans apply immediately and admin status comes from `ADMIN_EMAILS` at request time; why: JWTs would otherwise keep a banned or demoted user signed in; rejected storing roles in the token.
- Without `AUTH_SECRET`, a random secret is generated once into `.pglite/auth-secret`, except on Vercel, which must set it; why: a clean clone runs with zero env vars and still gets a non-guessable secret; rejected a hard-coded dev secret.
- The dev credentials login is on in development and test, opt-in with `GW_ENABLE_DEV_LOGIN=1` for production builds (e2e), and always off when `VERCEL_ENV=production`; why: e2e runs against `next start`; rejected enabling it by NODE_ENV alone.
- `proxy.ts` (Next 16's middleware) only redirects signed-out visitors away from write, edit, fork and admin pages; every page and server action re-checks with `requireUser`/`requireAdmin`; why: the proxy is a convenience, not the authorization boundary; rejected relying on the proxy.
- The magic-link form redirects to our own `/signin/check` page instead of Auth.js's default verify page; why: the design language applies to every page; rejected the stock page.
- "Change this season" is current members minus the faith's share snapshot at the season's start tick (0 for faiths founded later), and the podium says "down N after the schism" when the faith lost members and a fork of it appeared this season; why: matches the Faiths mockup copy from stored data; rejected tracking a separate counter.
- The season/all-time toggle is a pair of links (`?view=all`) rather than client state; why: shareable URLs, no client JavaScript, works without hydration; rejected a client-only toggle.
- Hidden (reported) faiths drop out of public standings, flock share and pane labels; their members count as Unaligned in public totals until an admin resolves the report; why: GAME.md §13 hides them from public pages while the apostle keeps preaching; rejected removing their members from the world.
- Revision history is its own page (`/f/[slug]/revisions`) with line diffs between revisions; why: keeps the faith page matching the mockup; rejected an inline accordion.
- "Report this gospel" reports the current revision and "Report this faith" the faith; both count toward the faith's unique open reporters for auto-hide; why: GAME.md §13 hides the faith, whatever the reported piece was; rejected per-target thresholds.
- Prophet handles render as plain text (there are no public user pages in v1); why: avoids links to nowhere; rejected linking to the agent page as the mockup placeholder does.
- The editor lints in the browser with the same pure `lintGospel`, `lintFaithName`, `detectParaphrase` and `countTokens` the server runs (300ms debounce), and the server re-checks everything on publish; why: identical messages client and server, no lint endpoint; rejected a lint API round-trip per keystroke.
- Every publish attempt (new, fork or edit) counts toward `publishRateLimit` before validation, so failed lints count (GAME.md §14); drafts autosave 2.5s after the last change under `draftSaveRateLimit`; why: the spec counts failed attempts; rejected counting only successful publishes.
- Forks need a free glass color immediately (no Narthex for forks), because the schism pull happens at publish; why: a queued fork could not receive movers; rejected deferring the pull to next season.
- The apostle style can be changed from the edit page; the change is stored as `pendingStyle` and applied at step 1 of the next tick; why: GAME.md §5.1; rejected applying it immediately.
- `Encounter.convictionAfter` stores the agent's final conviction (after conversion), and the roll ledger shows the rolled values from `rollResult`; why: the ledger needs both "44 to 25" (the roll) and "new conviction 40" (the conversion); rejected storing only the rolled value.
- The encounter page's outcome headline is written by the engine's templates from the stored outcome, never by the LLM (DESIGN.md don'ts); the judge's rationale shows as a labelled note; why: LLM words never state outcomes; rejected showing the rationale as the headline.
- The encounters index pages by whole ticks (`?before=` a tick) with outcome filters as links; why: stable URLs, and a tick is never split across pages; rejected offset pagination.
- The agent page lists only leanings above 0, plus the current faith at its conviction (as in the mockup); why: eight zero bars are noise; rejected listing every faith.
- OG cards render with `next/og` (Satori) in the Node runtime from Fontsource `.woff` files read from `node_modules` (traced for Vercel with `outputFileTracingIncludes`); Satori cannot read CSS variables, so the card uses a hex mirror of the tokens in `lib/ui/tokens.ts`, used nowhere else; why: no network font fetches, one documented exception to "no hex in components"; rejected fetching Google Fonts at render.
- Card text (kicker, headline, quote, score line) is written by the engine at emit time and stored on `ConversionCard`; the route only renders it; why: cards are immutable records of the moment; rejected recomputing copy at render.
- Approving a draft post marks it approved, sends it to `LogSocialProvider` (a `SocialLog` row), then marks it posted with a `log://` URL; `XSocialProvider` throws "not configured"; why: GAME.md §15, no real posting in v1; rejected a no-op approve.
- Admin "Reseed world" runs the same `seedDemoWorld` as `pnpm db:seed` inside the server process (behind a typed RESEED confirmation); why: on PGlite the server owns the database, so a CLI reseed would need the server stopped; rejected a CLI-only reseed.
- Non-admins get a 404 for `/admin` (not a 403); why: don't advertise the console; rejected a forbidden page.
- Unknown URLs inside the site render the shell's not-found page through a `(site)/[...missing]` catch-all; route errors show a design-language error boundary that names the likely cause (a busy PGlite database) and offers "Try again"; why: no page falls out of the design language; rejected the stock Next.js pages.
